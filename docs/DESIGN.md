## 工作区与导航

**设计基线：让内容先于装饰。** 这是一套嵌入 Studio 的工作界面，不是独立网站。导航、列表、正文组成连续的浅层表面；用层级、间距和轻选中态组织信息。不另加品牌横幅、大面积强调色、深底卡片或成排的有框操作按钮。

| 宿主顺序 | 显示名／视图 | 主导航图标 | 内容区 |
| --- | --- | --- | --- |
| 1 | Ekko Tools／`translate` | `assets/icon.png` | 语言栏、服务选择、原文和译文 |
| 2 | Ekko 邮件／`mail` | `assets/nav-mail.png` | 邮箱导航、列表、详情或编辑器 |
| 3 | 阅读／`reading` | `book` | 来源导航、文章列表、正文或简报 |
| 4 | 设置／`settings` | `settings` | 设置分区和表单；支持 `?section=` 定位 |

- [插件清单](../plugin.json) 的 `views` 和 `navigation.main` 管理 Studio 入口，四项都注册在 `workspace`。 [App](../src/client/App.tsx) 在客户端分流；`workspace-sidebar` 不再渲染重复侧栏。`Alt+1/2/3` 在插件工作区内切换翻译／邮件／阅读；已打开视图保留在 `hidden` 容器内。
- [启动入口](../src/client/main.tsx) 先用宿主底色绘制，优先复用当前身份的首屏、外观和列表缓存。无首屏数据时显示骨架，失败就地重试；缓存存在时先显示内容，安静刷新，不因为切页重播全屏加载。
- 翻译、邮件、阅读使用工作区宽度；设置桌面布局有自己的版心。主从式工作区内，列表和内容按需独立滚动；网格子项允许收缩（`min-width:0;min-height:0`），页面本身不横向滚动。

### 分端规格

桌面 Studio、Studio 网页和 Studio App **共用同一套插件界面**。宿主负责外部导航、主题、通知和确认；插件只负责 iframe 内布局。适配由 **iframe CSS 宽度、高度及指针类型**决定，不以 Windows、浏览器或手机型号分支。

| 运行环境 | 布局与操作 | 必查差异 |
| --- | --- | --- |
| 桌面 Studio（Windows 等） | 宽窗口用完整工作区；缩窄窗格时与网页应用同一断点。鼠标悬停是附加反馈，键盘可用 Tab、Esc 和页面快捷键 | 宿主侧栏不可重复；写邮件后左栏仍可点；关闭抽屉、切页或保存失败时不可留下透明遮罩拦截点击 |
| Studio 网页 | 同宽度、主题、指针下沿用桌面布局；窄浏览器或浏览器缩放也会触发抽屉和单屏。滚动在插件各窗格内，不能借浏览器整页滚动修复溢出 | 检查浏览器缩放、下载与剪贴板权限；复制受限时保留可选择文本。浏览器刷新与工作区内部切换分开验收 |
| Studio App / 移动 WebView | 宿主导航之外，插件窄屏采用抽屉、单列和明确返回；不用悬停作为唯一入口。横屏或大平板可能保留双窗格 | 实测软键盘、底部安全区、系统选择器、跨网络连接与保存反馈；桌面调窄不能替代 iOS 宿主测试。传输约束见 [移动桥接契约](CONTRACTS.md) |

### 布局断点

宽度指**插件 iframe**，不是设备标称宽度；以下 `≤` 均包含边界。

| 宽度 | 布局变化 |
| --- | --- |
| `≤1220px` / `≤1180px` | 阅读／邮件分别收紧桌面三栏 |
| `≥1000px` / `≤999px` | 翻译在宽屏用双栏，窄于该布局时编辑区和工具行堆叠；不等于手机模式 |
| `≤980px` | 邮箱导航和阅读来源改为带遮罩的抽屉，宽度分别为 `min(320px,86vw)`、`min(330px,88vw)`。`761–980px` 仍可保留主从窗格 |
| `≤760px` | 邮件／阅读在列表、详情间切换，两者外壳圆角均为 16px；设置分区移到顶部横向滚动，表单主网格转单列；窄屏背景优先移动图 |
| `≤400px` / `≤350px` | 邮件详情操作行／阅读详情工具栏分别允许换行，返回操作仍优先显示 |
| `≤380px` 且 `pointer:coarse` | Markdown 格式工具变四列；仅调窄桌面网页不会触发该项 |

断点样式见 [mobile.css](../src/client/styles/mobile.css)，可见性逻辑见 [useIsNarrow](../src/client/hooks/use-is-narrow.ts)。移动端视口高度由 `--ek-viewport-height` 同步，监听 `visualViewport` 变化；贴底内容避开 `env(safe-area-inset-bottom)`，抽屉兼顾左侧安全区。视觉隐藏、`hidden`/`inert`、抽屉关闭和焦点回落必须一起检查。移动端输入字号下限 16px，通用控件最小 44px；局部历史例外见对应页面。不要用全局横向隐藏代替修复控件溢出。

## 主题与设计令牌

色值、字号和尺寸是**回退值**，不是应当硬编码的最终画面。跟随模式由 Studio 注入并实时更新主题变量；自定义模式由全局设置生成 `--ek-*`，单个区域覆盖优先于全局值。Web／移动壁纸独立于跟随开关。真正的定义见 [design-tokens.css](../src/client/styles/design-tokens.css)、[theme.ts](../src/client/theme.ts)、[appearance.ts](../src/client/appearance.ts) 和 [外观默认值](../src/shared/appearance.ts)。

| 角色 | 应使用的令牌 | 回退／用法 |
| --- | --- | --- |
| 页面 / chrome | `--ek-bg-page` / `--ek-bg-shell` | 浅色页面 `#fafafa`，深色页底回退 `#1a1a1a`；chrome 优先取宿主区域 |
| 导航 / 内容 | `--ek-bg-sidebar` / `--ek-bg-content` | 尊重宿主侧栏和主表面；没有宿主值时浅色以白为回退 |
| 卡片 / 输入 / 对话与菜单 | `--ek-bg-surface` / `--ek-bg-input` / `--ek-bg-raised` | 分用途取值，不复制页面色。自定义深色默认卡片为 `#2a2a2a` |
| 主文字 / 次文字 / 弱提示 | `--ek-text` / `--ek-text-2` / `--ek-text-muted` | 浅色 `#1a1a1a` / `#666666` / `#999999`；弱提示不承载唯一的关键说明 |
| 边框与分隔 | `--ek-border` / `--ek-border-light` | 浅色 `#e0e0e0` / `#ebebeb`；区域可用 `--ek-border-{sidebar,content,card,input,overlay,chrome}` |
| 主操作 / 链接 / 焦点 | `--ek-accent` / `--ek-on-accent` / `--ek-link` / `--ek-focus` | 浅色强调 `#333333`，对比前景 `#ffffff`；自定义和宿主强调会调整前景对比 |
| 交互与反馈 | `--ek-bg-hover` / `--ek-bg-selected`、`--ek-success` / `--ek-warning` / `--ek-error` | 悬停、选中和结果各有独立语义；错误或连接状态同时显示文字，不只显示颜色 |

**排版与几何。** UI 和阅读字体优先继承宿主；无宿主字体时使用系统中文无衬线回退，RSS 正文样式例外。基础 `--ek-fs-base` 14px，`xs/sm/md/lg/xl` 约为 11/12.5/16/20/25px；元信息用小号次文字，主正文用基础字号，主题／详情标题用较大字号。默认 UI 行高 1.6，字重基准 400/600；代码用 `--ek-font-mono`。间距 `--ek-sp-1` 至 `--ek-sp-6` 为 4/8/12/16/20/28px，随 `--ek-spacing-scale` 缩放。卡片 8px、输入 6px、胶囊 999px、常规／紧凑控件 36/32px、分隔 1px；模块局部值不提升为全局标准。

**壁纸与层次。** 没有壁纸或渐变时，不加载默认照片、不强加深蓝底或通用模糊。壁纸模式下工作区背景由独立层绘制；浅色玻璃回退不透明度按 chrome／侧栏／内容／卡片／输入／浮层为 60%／78%／86%／72%／72%／72%，宿主或用户可覆盖，深色回退不同。邮件和阅读的外壳留透明，由实际窗格取样；移动设置减少叠层。常态阴影默认为无，浮层或定制外观才使用对应 `--ek-shadow-*`。新组件不私加 `backdrop-filter`，复用 [区域表面规则](../src/client/styles/studio-surfaces.css)。

**样式顺序。** [入口](../src/client/main.tsx) 依次装载 `fonts → design-tokens → app → compat → redesign → mail-client → theme-studio → reading → mobile → studio-surfaces → studio-geometry`。主题桥接与外观再写根元素变量。不要从前层的单条规则推断最终外观，也不要把历史文件中已被覆盖的颜色当令牌。

### 表面归属

| 区域 | 现有实例 | 扩展时如何选用 |
| --- | --- | --- |
| `chrome` / `sidebar` | 工作区框架；邮箱文件夹栏、阅读来源栏、设置导航 | 框架与导航用区域颜色和边界；选中行使用 `--ek-bg-selected`，不把整栏染成强调色 |
| `content` | 邮件列表／详情、阅读详情、设置主体 | 负责主滚动和主要背景；标题、工具栏与正文属于同一表面，默认不再包卡 |
| `card` | 翻译原文／译文、语言／服务块、设置表单和账号卡 | 只有需要并列对齐或分组时才单独取表面；设置正文容器本身透明 |
| `input` | 单行字段、选择器、可编辑区 | 标签＋字段是一组；邮件编辑、回复和邮件搜索使用透明内层，手机阅读搜索同样透明、聚焦才显底 |
| `overlay` | 发现订阅、阅读菜单、AI 解读、划词 | 使用浮层材质与局部阴影；抽屉保留明确的关闭操作和遮罩，非模态辅助面不吞掉底下正文的操作 |

在 [区域几何](../src/client/styles/studio-geometry.css) 中，主容器、侧栏、卡片、输入、浮层分别取对应该区域的圆角；图标、列表行等小元素通常用 `--ek-radius-sm`。窄屏覆盖是局部规格。浅深色为空间材质，已读／选中／错误为交互状态，两者独立；不能用「深色」表示已按下或用背景图片充当分隔线。

## 通用组件与状态

| UI 模式 | 现有入口／用法 |
| --- | --- |
| 按钮与工具栏 | `.primary` 用于当前任务的主要提交；`.compact` 用于次操作，`.ibtn` 用于单图标。正文附近工具保持轻量，邮件覆盖为默认无描边；有语义的按钮同时提供名称、禁用状态和焦点反馈 |
| 图标 | [Icon](../src/client/components/States.tsx) 为 `24×24` SVG 画板、1.8 描边、圆端、`currentColor`；`sm` 用在密集工具栏。SVG 自身隐藏于辅助技术，由按钮的 `aria-label` 提供动作名，必要时补 `title` |
| 选择器 | [Select](../src/client/components/Select.tsx) 是触发按钮和门户 `listbox`，统一下拉外观，贴视口翻转、限宽、限高；方向键、Home/End、Esc，选中／Esc 后回焦触发按钮 |
| 标签与选中项 | [Tabs](../src/client/components/Tabs.tsx) 提供左右键与 Home/End；侧栏筛选用 `aria-pressed`，选中项整行浅底提亮；来源色只用于账号标识，[ProviderIcon / Source](../src/client/components/AccountChip.tsx) 不充当导航主题色 |
| 结构与表单 | `.section-heading`、`.card.settings-form`、`.form-grid`、`.row.wrap`、`.small`。一个标签紧邻一个控件；长字段可跨列；输入与卡片不双重叠色。开关使用原生 checkbox 或有名称的 `role="switch"`，不靠装饰传达值 |
| 空白 / 失败 / 加载 | [State](../src/client/components/States.tsx) 为常见邮件和翻译状态提供图标、标题、可选详情和操作。空态 `status`，加载 `aria-busy` 与骨架，警告／错误按重要程度语义化；模块也可用同样语义的局部状态 |

- **状态落在发生的位置：** 首屏未知用骨架；数据确定为空就保持稳定空态；有数据的后台更新不盖掉内容。首次加载、分页、上传、提交分开计时；失败就地说明并保留重试入口，编辑失败尽量保留用户输入。
- **操作层级：** 普通结果可用 Studio 通知，提交失败、部分成功或结果未确认要在操作位置保留说明。不可逆操作用 `ctx.ui.confirm`，不要因为超时就自动重试写入或发信。
- **交互基线：** 优先原生按钮、链接和表单；焦点用 `--ek-focus` 而非固定蓝色。手机通用目标 44px、常规文本输入不低于 16px；旧邮件详情工具条有 28px 紧凑例外，不作为新模块范本。缩短过渡并尊重减少动态效果。文案集中在 [i18n.ts](../src/client/i18n.ts)，用 `t` / `tFormat`，检查中英文和长文本溢出。

### 组件细则

- **按钮与选择态：** 主按钮只标记当前步骤最重要的操作（如发送、保存）；工具图标可无常态边框，但正常／悬停／键盘焦点／禁用仍需可区分。用于切换的按钮显示持久选中态并标记 `aria-pressed`，不把按住时的视觉反馈当作选中。删除不抢占主操作，靠明确的动作名和确认。
- **下拉层：** 常规目标宽度取触发器宽和 190px 的较大值，再按视口两侧各 8px 限宽；目标高度上限 280px，空间不足时向上翻转并独立滚动。禁用选项不能提交；选中或 Esc 后回焦；外部点击收起，Tab 继续正常遍历，不把普通下拉当成模态对话框。
- **横向容量：** 图标、简短动作和进度按钮不挤压到不可点，把可伸缩空间留给搜索、地址、标题。列表行可截断，详情保留可读值。手机优先缩短文案、允许换行并局部滚动；只有设计明确的工具轨才允许横滚。
- **提示与遮挡：** 错误需说明发生位置、可采取的下一步；诊断编号可用于排查，不替代说明。对话框、抽屉打开时下层不可误触；关闭后遮罩不能留在页面上。辅助浮面可滚动，但不占用页面唯一返回通道。

## 翻译

实现：[Translate](../src/client/views/Translate.tsx) · [工作区样式](../src/client/styles/redesign.css) · [移动覆盖](../src/client/styles/mobile.css)。

- **顶部语言行：** 源语言（默认自动检测）→ 交换 → 目标语言（默认自动中英互译）；服务选择单独分组，默认跟随设置，标明未配置并禁用该选项。无可用服务时在工具行下显示「去配置」，跳转设置的翻译分区。
- **原文：** 标题与 `当前 / 5000 字` 同行，下方为可粘贴编辑的文本区，操作栏放「清空」「粘贴」和划词开关。空文本不请求，超限显示错误。自动检测结果单独显示，不替换用户选项。
- **译文：** 独立区显示目标语言、可选择的纯译文和「复制」「重新翻译」，完成后显示实际服务和缓存标记；未翻译时显示占位及禁用操作。不设额外主翻译按钮、不展示双语对照或最近翻译历史。
- **执行：** 停止输入约 900ms 自动执行；`Enter` 立即翻译，`Shift+Enter` 换行，输入法组词中不提交。`Ctrl/Cmd+Enter` 执行、`Ctrl/Cmd+Shift+S` 交换、`Ctrl/Cmd+Shift+C` 复制。语言、服务或原文变化时作废旧请求；配置错误引导设置，其他失败就地重试。
- **窄屏：** 桌面双栏，低于 1000px 按原文、译文顺序堆叠；手机保持源语言／交换／目标语言同一行，服务独占下一行。工具行与输入使用同系表面，壁纸模式下原文 textarea 不另叠输入底色。

| 环境 | 细节 |
| --- | --- |
| 桌面 Studio／宽网页 | 上方语言与服务工具区；下方左原文、右译文。服务不可用的说明放工具区下方；复制失败可回落到选中译文，由用户手动复制。大小调整与界面刷新不应被当成重新翻译的动作 |
| 平板／窄网页 | 先语言、后服务，原文在译文上。局部空提示、字符数和操作名称不折叠成只能悬停查看的图标 |
| 手机 WebView | 语言行 `1fr / 44px / 1fr`（两侧可收缩），服务行至少 48px；原文、译文阅读区分别至少 160px、180px，译文行高 1.85。工具可换行，保留软键盘下的自然纵向滚动，输入法组词时不抢提交 |

**反馈位置：** 未翻译提示在译文区；当前请求的「翻译中」以及超限／鉴权／请求错误在两栏之后。原文变化时替换过期译文；切换到其他工作区再返回时，不能将脱离当前输入的迟到结果显示为最新译文。

## 邮件

### 收件箱与账户导航

实现：[Mail](../src/client/views/Mail.tsx) · [mail-client.css](../src/client/styles/mail-client.css)。桌面是「左侧邮箱导航 / 中间列表 / 右侧阅读」；宽屏列宽为 220px / 330–420px / 剩余空间，`≤1180px` 收为 172px / 250–310px / 剩余空间。`≤980px` 用「邮箱导航」抽屉，`≤760px` 列表和正文互斥。

| 邮箱菜单顺序 | 描边图标 | 行为 |
| --- | --- | --- |

### 邮件详情

实现：[MailDetail](../src/client/views/MailDetail.tsx) · [MailBodyFrame](../src/client/components/MailBodyFrame.tsx) · [详情样式](../src/client/styles/theme-studio.css)。

- **回复 / 附件 / 删除：** 回复表单原地展开并显示收件人，使用当前邮箱发送；失败保留输入，成功仅说明发件服务器接收。附件行显示文件名、大小和类型／拦截原因，下载可显示进度和取消。删除需确认并移入服务器垃圾箱，成功减少列表与计数，失败保持详情；不把不支持移动的邮箱当作成功。

- **列表范围和反馈：** 上一封／下一封基于当前可见列表，不能跳进其他筛选。取信中及失败时顶部返回保留；删除失败在详情内容顶部反馈。回复展开时聚焦文本区，失败提示在回复动作旁；收到仅含附件的邮件时显示无正文说明，不展示白板。
- **桌面／网页正文：** HTML 框高 `min(72vh,760px)`、至少 360px，独立滚动。正文外保持工作区主题；邮件内部颜色来自原信，不把邮件背景扩展到详情顶部和按钮区。
- **手机详情：** 到 400px 及以下允许第二层操作栏换行，其余窄屏必要时只滚动操作栏，不滚动整页。地址、日期用单行省略；附件文件名省略但动作保留。回复键盘弹出时可滚到发送／取消；向下阅读后仍能由顶部返回。

## 阅读

实现：[Reading](../src/client/views/Reading.tsx) · [reading.css](../src/client/styles/reading.css)。桌面栏宽为来源 196–224px、列表 296–352px、详情自适应，`≤1220px` 收紧为 184–204px / 276–320px / 自适应。来源可手动收起；打开文章时收起列表，专注模式再隐藏来源，只保留正文。`≤980px` 来源改抽屉，`≤760px` 列表和详情互斥，进入内容后自动收起抽屉。

### 来源与文章列表

- **左栏：** 顶部 RSS 标识、订阅数与未读数；快捷项依次为全部、未读、收藏、今日简报。下面是可展开的分组树和订阅源，源行用站点图标／首字母回退、站名、右对齐未读数。底部导入和导出 OPML，无源时提供「添加第一个订阅」和「浏览精选订阅」。
- **管理：** 加号在对应标题下展开分组名或订阅网址表单。分组／同组订阅支持拖动排序；订阅菜单可移动到分组、全部标为已读、单源刷新、重命名和删除；分组菜单提供删除。重命名为独立对话框，显示 URL、名称输入、取消和保存。
- **列表头尾：** 来源展开／收起、搜索标题／摘要、全部标为已读、刷新订阅；底部显示篇数、未读与上次同步或「仅本地缓存」。首次请求显示加载，空列表区分没订阅和筛选无匹配，并给出添加或清除筛选入口。
- **列表行：** 来源与时间置于顶行；下面是可选缩略图与标题、摘要、作者／收藏／AI 摘要等元信息。手机缩略图 56px，摘要最多两行。有下一页时在列表内加载（本地每页 30 条），结束显示已加载总数；打开文章和滚过列表顶部的条目可以更新已读状态。

### 正文与今日简报

- **正文头部两行：** 返回列表单独占左侧；右侧依次为专注阅读、AI 解读、收藏、标为未读、打开原文。第二行展示来源、文章标题和元信息，避免挤进工具按钮。未选文章时显示「选择一篇文章」，取正文时仍保留返回入口。
- **正文样式：** 长文在详情内滚动；HTML 通过 [正文渲染器](../src/client/sanitize/html-allowlist.ts) 生成独立 sandbox iframe。默认纸白、衬线、16px / 1.85 行高、720px 版心；可在阅读设置切换暖褐／深色、字体与自定义 CSS。正文主题不同于工作区主题，不应该渗到列表或顶部按钮。
- **翻页：** 在当前筛选／来源范围内，滚到顶部继续向上或底部继续向下打开邻文；需要时读取下一页。手机支持触摸手势和带禁用状态的「上一篇／下一篇」按钮，正文基础字号至少 17px 并预留底部操作区。
- **今日简报：** 左侧入口在详情区打开，保留 AI 标识、标题、日期和生成／重新生成操作；有结果后按分组展示内容。使用独立生成忙碌态，不用列表刷新替代；抽屉宽度下提供「返回列表」。

- **桌面／网页阅读：** 列表收起后正文获得主要空间，来源显示与列表显示各自管理；专注阅读只剩正文。返回恢复文章列表，而「打开原文」是独立外部链接。滚轮翻页只在正文到边界时触发；不因读到一张图片就跳转文章。
- **手机阅读：** 详情顶部与独立滚动的正文分离。标题可换行；`≤350px` 时按钮组在返回之后独占一行。正文底部右侧有避开安全区的 44px 上／下篇按钮，首尾不可用时弱化并禁用；不能仅靠触摸手势导航。
- **简报内容：** 标题下有总览和生成时间，主题分组下每条是可点击摘要，进入对应文章，不另开与原文重复的工作区。手机保留清楚的返回层级，生成中不隐藏已显示内容。

### 发现订阅源与 AI 解读

- **发现订阅源**是阅读工作区内的覆盖对话框，不改变路由。结构为标题和关闭 → 搜索和选分组 → 分类 → 独立滚动的卡片列表。现有目录为 9 类 27 个来源，卡片含站名、分类、描述、站点／桥接标识、预览和订阅操作；已订阅用状态替换按钮。无结果可清除筛选，按 `Esc` 关闭。宽度上限 860px，`≤1100px` 卡片改单列。实现：[ReadingDiscover](../src/client/views/ReadingDiscover.tsx) · [订阅目录](../src/shared/feed-catalog.ts)。
- **AI 解读**是正文内的非模态浮面，打开后正文仍可读、可滚动；桌面从标题栏拖动，移动端贴底且不拖动。内容依状态为生成入口、生成中、一句话摘要／要点／值得一读、失败与重试；已有结果时可重新生成，缺配置提示转阅读设置。用关闭或 `Esc` 收起，不做全屏跳转。

- **发现窄屏布局：** 面板最大高度 `min(76%,700px)`；`≤720px` 将搜索和目标分组上下排布。单列卡片保留站点、描述、预览与订阅；失败提示在分类与列表之间，保留查询条件。预览走外链，不替换弹窗结果列表。
- **移动解读层：** 贴底面板最大高度 `min(72dvh,640px)`，避开安全区，关闭按钮 44px。内容多时滚动面板本身，桌面拖动不是手机前置条件。

### 分区版式与反馈

**桌面 Studio／网页：** 左栏沿表单顶部定位，分区按钮默认高 40px。并列字段遵循阅读顺序，长地址、密钥和说明跨列。按钮和状态与所属表单成组，不做跨分区的全局提交。**手机：** 顶部导航可横向滑动，分区按钮 44px，选中与未选中沿用桌面语义；沿同一字段顺序单列展开，原生时间、数字、文件和密码控件保留相应系统输入方式。除外观保存栏外，操作留在所属表单末端，避免多个贴底栏叠加。

| 分区 | 实现细节与分端验收 |
| --- | --- |
| 邮箱账号 | 重授权复用顶部表单并自动滚到表单；保留账号说明但密钥留空。别名直接在对应账号卡修改。服务商改变时检查自建服务器行的显隐；手机长邮箱不可挤掉操作，账号卡的动作可换行 |
| 翻译服务 | 只展示所选服务的字段；密钥不回显。**测试连接先保存当前表单，再测试**，不是无副作用预检；结果区域与普通保存反馈分开。手机检查长接口地址和模型值、可换行的保存／测试按钮，以及术语表输入中的换行 |
| 阅读设置 | 轮询 `5–120` 分钟、保留 `7–365` 天、单源 `50–2000` 篇；正文设置字号 `12–24px`、行高 `1.4–2.4`、版心 `520–1024px`。代理验证和保存失败在本区，不打断阅读页；恢复默认仅重置表单中的正文样式，需保存整页 |
| 外观 | 桌面并排预览两张壁纸，手机依次堆叠；是否使用移动壁纸看宽度，不看卡片名称。范围选项、颜色、滑块逐组展开，手机仍可从贴底栏保存，不需要回到页面顶部 |
| 通知设置 | 开关、免打扰时段、账号静音分层；时段跨午夜时也需正确反馈当前状态。手机容许时间控件换行、地址折行，保存应在静音列表之后而不是随单个账号触发 |
| 数据与诊断 | 保留缓存统计、清除／刷新，并与诊断导出分组。窄屏可换行但不隐藏单位和结果；Web／App 要分别检查文件下载能否由宿主处理，不能只看按钮点击有反馈 |

### 外观设置细节

- **背景卡：** Web 端与移动端并排，间隔 12px，手机改纵向。每张含用途、截断的文件名／回退说明、预览和上传／移除；预览至少 168px 高，无图片时显示虚线占位。接受 JPG、PNG、WebP 原图，上限 20MB。上传即预览，按槽位持久化，不要求再点「保存外观」；上传中只在对应背景卡标明状态。`≤760px` 优先移动图，没有则回退 Web 图，再回退渐变或 Studio 底色。
- **跟随与自定义：** 跟随时隐藏高级字段；自定义先选调整范围。全局提供明暗切换（只换仍为默认值的配色）、四种字体、页面／表面／文字／链接／边框／强调色、尺寸和排版、全局不透明度、背景显示方式／位置／渐变终点。修改即时预览，不等于已保存。
- **区域设置：** chrome、侧栏、内容、卡片、输入、浮层共六区。区域可覆盖背景、边框、不透明度、模糊、圆角和阴影；未设项标为「继承」。单项重置只撤销当前项覆盖，「清除此区域覆盖」撤销区域覆盖，不清其他区。
- **保存与恢复：** 「保存外观」为主按钮，「恢复默认」为次操作；恢复默认会清除自定义背景。手机保存栏贴底避开安全区，成功／失败紧邻按钮。保存、恢复与上传显示各自文案；每次外观 RPC 最多等 15 秒。保存超时会额外等待最多 5 秒，回读服务端设置以确认结果，不重发保存或下载背景。无法确认时显示错误并保留修改，允许手动重试。分块上传按每次 RPC 计时，不承诺整张图 15 秒内上传完。

| 控件组 | 界面顺序与调整范围 |
| --- | --- |
| 主题与字体 | 浅色／深色分段按钮；字体按 Comic、系统、宋体、等宽排列，各用自己的字体样式预览。当前项有持久选中态 |
| 颜色 | 页面、表面、正文、次要、弱化、边框、链接、强调依次出现；色块与 `#RRGGBB` 同时显示，可单项还原当前方案默认值 |
| 尺寸与排版 | 字号 `12–20px`、行高 `1–2.4`、圆角 `0–32px`、控件高度 `30–56px`、边框 `1–4px`、间距 `0.8–1.6×`、字间距 `-1.5–1.5px`、阴影 `0–2`、正文宽 `480–1600px`。滑块旁显示当前值／单位，可恢复单项 |
| 背景 | 全局滑块另含渐变角 `0–360°`、压暗 `0–0.85`、模糊 `0–24px` 和可继承不透明度 `0–1`；背景组选择铺满／完整显示／原始尺寸、居中／顶／底／左／右，以及可继承的渐变终点 |
| 分区域 | 先背景和边框色，再背景不透明度 `0–1`、模糊 `0–30px`、圆角 `0–32px`、阴影 `0–2`。未覆盖的输入圆角取全局减 2px（不低于零），侧栏／内容区默认零；不同区域的壁纸混合值见主题章节 |

**状态的边界：** 即时预览、已保存、确认失败是三件事。保存栏显示操作名与错误码，存在时另显示诊断编号。遇到 iOS 超时，用真机复现「首次点保存 → 页面是否重载 → 操作结束 → 重开读回」，分别覆盖同网和不同网络；还需单独跑壁纸上传。具体移动请求尺寸与分块规则见 [契约](CONTRACTS.md)，不要把超时直接归因为网络，也不要把连接条件当作布局差异。

### 实现顺序

1. **定入口和返回。** 独立任务才新增 Studio 工作区入口（同时接清单与 `App` 分流）；已有任务的设置、编辑、浏览优先扩展现有分区或窗格。记录关闭后回到哪一行／按钮。
2. **先写结构，再套材质。** 排定标题、主操作、筛选、内容、状态的顺序。复用现有容器和组件；添加样式时使用语义令牌并限定模块选择器，不改全局按钮或输入来修某一页。
3. **列出状态和退出路径。** 初次加载、空、无匹配、刷新、提交中、成功、错误分别注明呈现位置；仅当前操作忙碌时禁用相关控件。需要网络等待的提交有可恢复的超时；失败后保留输入，不自动重发可能已成功的操作。
4. **接宿主能力。** 插件 iframe 业务通过 `ctx.rpc`，不直连网络、不用 `localStorage`；信息提示、确认、跳转走 `ctx.ui`。签名、状态字段随 [契约](CONTRACTS.md) 更新，并遵守 [开发规范](DEVELOPMENT.md)。
5. **从窄屏校验布局。** 先看 320px，再看 390px 和横屏；检查滚动容器、底部安全区、键盘弹起、抽屉关闭和焦点恢复。确认 `980px` 的抽屉与 `760px` 的主从切换是独立行为。
