# ekko-tools 产品需求（PRD）

本文是用户视角的产品需求摘要。0.1.0 覆盖翻译、统一收发件箱、RSS 阅读与统一设置页；
后续工具模块沿用同一套 RPC、契约、分区存储与设置体系扩展。

## 产品定位

Ekko Studio 侧栏内的**可扩展工具插件**：翻译帮助用户跨语言工作；邮件把
163/QQ/Gmail 和自建 IMAP/SMTP 聚合到一个面板；阅读提供 RSS/Atom/JSON Feed 聚合、
本地归档与 AI 摘要。三者共享设置、通知、外观和加密凭据基础设施。

## 用户故事（MVP）

- 翻译（A 类）
  - A01 作为用户，我粘贴或输入 ≤5000 字文本，选源/目标语言（或自动检测）一键翻译，看到字数与词数统计。
  - A02 我可以交换语言方向（自动检测时用检测结果回填），复制译文（受限环境降级为选中提示），重新翻译。
  - A03 翻译后端可插拔（百度 / DeepL / 宿主模型 / OpenAI 兼容），全部使用真实服务，缺配置给可操作错误。
  - A04 面板内划词出现精简浮条，可直接译文或送入主翻译框；仅作用于插件自身 DOM。
- 邮件（B 类）
  - B01 我添加 163/QQ/Gmail 账号（授权码/应用专用密码）或自建 IMAP/SMTP 账号（邮箱密码与服务器），凭据一次提交即加密，前端只见"已配置"。
  - B02 统一收件箱聚合多账号：列表/详情/刷新、未读标记、按账号筛选、主题/发件人搜索、分页。
  - B03 详情支持正文（清洗 HTML + 纯文本回退）、附件下载（危险类型与超限拦截）、远程图片自动加载、原地回复。
  - B04 正文可整封翻译，逐段进度、单段重试、断点续译；列表"已译"标记。
  - B05 连接失败保留账号状态，可重连/重新授权/删除；单账号失败不隐藏其他账号邮件。
- 设置（C 类）
  - C01 Provider、百度/DeepL/OpenAI 凭据、划词开关、日志级别、账号管理集中在设置页；诊断可导出（脱敏）。
  - C02 可对当前 Provider 做连接测试（返回耗时/错误），并查看、清理当前分区的翻译缓存。
- 阅读（D 类）
  - D01 支持 RSS 2.0、Atom、RDF 与 JSON Feed 订阅，提供分组、OPML 导入/导出和后台轮询。
  - D02 提供 27 个高热度内置源，支持分类筛选、搜索、一键订阅和已订阅状态。
  - D03 文章与订阅状态写入本机 SQLite，支持全部/未读/收藏、搜索、已读同步和连续滚动。
  - D04 支持全文提取、远程图片、正文样式自定义与宿主模型/OpenAI 兼容摘要。

## 非目标（本期不做，仅预留）

OAuth、全文索引、复杂规则、本地离线模型管理（LibreTranslate/Argos 仅在
Provider 抽象层面预留，不接实现）。更多工具模块在后续版本按同一架构扩展。

## 关键约束（摘自任务书 §3）

契约先行（contracts/plugin.json + harness:check）；权限最小化（api.read/api.write/ui）；
凭据按 run.identity（user+profile）分区加密存储；IMAP 默认只读，服务器已读回写需显式开启；
回复通过 TLS/STARTTLS SMTP；单 RPC 120s 上限内
重试总耗时 ≤90s；错误码映射为可操作中文（界面文案 zh/en 集中于 src/client/i18n.ts）。

## 发布边界（0.1.0）

首个公开版本提供可独立安装的预构建产物，不携带任何开发者本地数据库、账号、邮件或订阅内容。
真实邮箱/百度/DeepL/OpenAI 的最终联调仍取决于用户自己的网络与凭据；未配置时界面返回可操作错误。
